Certainly! Below is a Python function named `dijkstra_shortest_path` that implements Dijkstra's algorithm to find the shortest paths from a given starting node to all other nodes in a weighted graph. The graph will be represented using an adjacency list, where each key is a node and its value is another dictionary representing the neighboring nodes and their associated edge weights.

```python
def dijkstra_shortest_path(graph, start):
    # Initialize distances with infinity for all vertices except the start vertex
    distances = {node: float('inf') for node in graph}
    distances[start] = 0

    # Priority queue to store (distance, node) pairs. Python uses tuples as items by default.
    priority_queue = [(0, start)]

    while priority_queue:
        # Extract the node with the smallest known distance
        current_distance, current_node = min(priority_queue, key=lambda x: x[0])
        
        # The node becomes processed when its corresponding entry in the queue is removed and not considered again.
        priority_queue.remove((current_distance, current_node))

        for neighbor, weight in graph[current_node].items():
            distance = current_distance + weight

            # Only consider this new path if it's better
            if distance < distances[neighbor]:
                priority_queue.remove((distances[neighbor], neighbor))
                distances[neighbor] = distance
                priority_queue.append((distance, neighbor))

    return distances

# Example usage:
graph = {
    'A': {'B': 1, 'C': 4},
    'B': {'A': 1, 'C': 2, 'D': 5},
    'C': {'A': 4, 'B': 2, 'D': 1},
    'D': {'B': 5, 'C': 1}
}

start_node = 'A'
print(dijkstra_shortest_path(graph, start_node))
```

### Explanation:
- **Initialization**: We initialize a dictionary `distances` to keep track of the shortest distance from the starting node to each node. Initially, all distances are set to infinity except for the starting node.
  
- **Priority Queue**: A priority queue is used to ensure that we always expand the current node with the smallest known distance.

- **Relaxation**: For each neighbor of the current node, if a shorter path is found through this node, the distance to the neighbor is updated and the new path is added to the priority queue for further exploration.

- **Processing Nodes**: We continue processing nodes until the queue is empty. At any point, once a node is processed (i.e., removed from the queue), it will not be considered again in subsequent iterations.

This implementation ensures that we find the shortest paths efficiently using Dijkstra's algorithm.
