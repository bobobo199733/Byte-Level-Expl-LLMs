Certainly! The Levenshtein distance is a measure of the difference between two sequences. It is defined as the minimum number of single-character edits (insertions, deletions, or substitutions) required to change one word into the other.

Here's an efficient implementation using dynamic programming in Python:

```python
def edit_distance(word1: str, word2: str) -> int:
    len1 = len(word1)
    len2 = len(word2)
    
    # Create a 2D array to store distances between substrings
    dp = [[0] * (len2 + 1) for _ in range(len1 + 1)]
    
    # Initialize the first row and column of the matrix
    for i in range(len1 + 1):
        dp[i][0] = i
    for j in range(len2 + 1):
        dp[0][j] = j
    
    # Compute the distances using dynamic programming
    for i in range(1, len1 + 1):
        for j in range(1, len2 + 1):
            cost = 0 if word1[i - 1] == word2[j - 1] else 1
            dp[i][j] = min(
                dp[i - 1][j] + 1,     # Deletion
                dp[i][j - 1] + 1,     # Insertion
                dp[i - 1][j - 1] + cost  # Substitution
            )
    
    return dp[len1][len2]

# Example usage:
word1 = "kitten"
word2 = "sitting"
print(edit_distance(word1, word2))  # Output: 3
```

### Explanation:

- **Matrix Initialization**: We initialize a 2D list `dp` where `dp[i][j]` represents the Levenshtein distance between the first `i` characters of `word1` and the first `j` characters of `word2`.
  
- **Base Cases**:
  - If one string is empty, the minimum number of operations required to transform it into the other string is simply the length of the non-empty string. This is why we initialize the first row and column with values from 0 to their respective lengths.

- **Dynamic Programming Table Construction**: For each character in `word1` and `word2`, we calculate the cost:
  - If characters match, the cost is 0.
  - Otherwise, the cost is 1 (indicating a substitution).
  
  Then, for each cell `dp[i][j]`, we compute the minimum of three possible operations:
  - Insertion: `dp[i][j-1] + 1`
  - Deletion: `dp[i-1][j] + 1`
  - Substitution: `dp[i-1][j-1] + cost`

- **Final Result**: The value at `dp[len1][len2]` will be the Levenshtein distance between the two strings.

This implementation is efficient for longer strings and avoids recomputing subproblems by storing intermediate results in a matrix.
