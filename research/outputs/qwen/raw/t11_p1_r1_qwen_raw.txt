Certainly! To solve this problem, we can use dynamic programming. The idea is to build a table `dp` where `dp[i]` represents the minimum number of coins required to make up the amount `i`. If no combination is found that makes up the given amount, we return -1.

Here's the Python function:

```python
def coin_change(coins, amount):
    # Initialize the dp array with a large value (infinity) for all amounts.
    # This will help us to find the minimum number of coins needed.
    dp = [float('inf')] * (amount + 1)
    
    # Base case: 0 coins are needed to make up an amount of 0
    dp[0] = 0

    # Fill dp table for all amounts from 1 to the target amount
    for i in range(1, amount + 1):
        for coin in coins:
            if i - coin >= 0:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    
    # If we could not make up the amount with given coins, return -1
    return dp[amount] if dp[amount] != float('inf') else -1

# Example usage:
coins = [1, 2, 5]
amount = 11
print(coin_change(coins, amount))  # Output: 3 (because 5 + 5 + 1 = 11)
```

### Explanation:
- **Initialization**: We initialize an array `dp` of size `(amount + 1)` with a large value (`float('inf')`). This is because we want to ensure that any valid count will be smaller than this initial value. The base case is `dp[0] = 0`, which means zero coins are needed to make up an amount of 0.
- **Dynamic Programming Table Filling**: For each amount from 1 to the target amount, and for each coin in the list of available coins, we update the dp table if using that coin helps us find a smaller number of coins. Specifically, `dp[i] = min(dp[i], dp[i - coin] + 1)`.
- **Result**: Finally, we check if `dp[amount]` is still infinity. If it is, then it means no combination was found to make up the amount with the given coins, and we return `-1`. Otherwise, we return `dp[amount]`.

This approach ensures that we find the minimum number of coins needed or determine that it's not possible.
