Here's a Python function called `merge_k_sorted_lists` that merges k sorted lists into a single sorted list using the heapq module, which is a built-in Python library:

```python
import heapq

def merge_k_sorted_lists(lists):
    # Create a heap from the input lists and iterate through it to get the smallest elements one by one.
    heap = []
    for list_ in lists:
        if list_:  # Check if the list is not empty
            heapq.heappush(heap, (min(list_), list_, 0))

    result = []
    while heap:
        _, curr_list, index = heapq.heappop(heap)
        result.append(curr_list[index])
        index += 1
        if index < len(curr_list):
            heapq.heappush(heap, (min(curr_list[index:]), curr_list, index))

    return result
```

```python
def merge_k_sorted_lists(lists):
    if len(lists) == 1:
        return lists[0]

    mid = len(lists) // 2
    left_half = lists[:mid]
    right_half = lists[mid:]

    merged_left = merge_k_sorted_lists(left_half)
    merged_right = merge_k_sorted_lists(right_half)

    return merge_two_sorted_lists(merged_left, merged_right)

def merge_two_sorted_lists(list1, list2):
    result = []
    i = j = 0

    while i < len(list1) and j < len(list2):
        if list1[i] <= list2[j]:
            result.append(list1[i])
            i += 1
        else:
            result.append(list2[j])
            j += 1

    # Concatenate the remaining elements from both lists.
    result.extend(list1[i:])
    result.extend(list2[j:])

    return result
```

Both implementations preserve duplicates, handle empty lists correctly, and are efficient for many lists when the number of input lists is relatively large compared to their sizes. The heapq implementation is more optimized as it has a O(n log k) time complexity, while the recursive solution has an O(n^2) time complexity in the worst case (when all lists have the same length).
