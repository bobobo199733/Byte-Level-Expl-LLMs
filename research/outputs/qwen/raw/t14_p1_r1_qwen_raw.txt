Certainly! The problem you've described can be solved using the concept of backtracking. Here's a Python function that generates all valid combinations of `n` pairs of parentheses:

```python
def generate_parentheses(n):
    def backtrack(s, left, right):
        if len(s) == 2 * n:
            result.append(s)
            return
        
        if left < n:
            backtrack(s + '(', left + 1, right)
        
        if right < left:
            backtrack(s + ')', left, right + 1)
    
    result = []
    backtrack("", 0, 0)
    return result

# Example usage
n = 3
print(generate_parentheses(n))
```

### Explanation:

1. **Function Definition**:
   - `generate_parentheses(n)`: This is the main function that initializes an empty list `result` to store all valid combinations and calls a helper function `backtrack`.

2. **Helper Function**:
   - `backtrack(s, left, right)`: This recursive function builds up the string `s` by adding either '(' or ')'. 
     - If the length of `s` equals `2 * n`, it means we have used all parentheses, and we add `s` to the result list.
     - If there are still fewer open parentheses than needed (`left < n`), we can add an opening parenthesis '('.
     - If there are more closing parentheses than opening ones (`right < left`), we can add a closing parenthesis ')'.

3. **Initialization**:
   - We start with `s = ""`, and both `left` and `right` counters set to 0.

4. **Result Collection**:
   - The function collects all valid combinations in the list `result`.

### Example Output:

For `n = 3`, the output will be a list containing the following strings:
```
['((()))', '(()())', '(())()', '()(())', '()()()']
```

This approach ensures that at any point during the construction of a string, there are always more open parentheses than close ones, and the total number of each is `n`.
